# Suisho Race

**目標: 同じ PC で YaneuraOu + 水匠に勝ち越す。** 大会では計算資源を揃えることが
多いので、相手に有利な条件を付けずに、この作業台 1 台の上で勝率 50 % を超えることを
目指す。このページはその進捗表で、改善ループを 1 周回すたびに 1 行足す。

## 測定条件

| 項目 | 値 |
|------|----|
| PC | Xeon E5-2630 v4 (5 コア) + RTX 2060 6GB、RAM 7GB |
| 相手 | YaneuraOu 9.80git (NNUE halfkp_512x2_8_64、AVX2、g++ でビルド) + 水匠10 (`suisho10_250413`) |
| 相手の設定 | **本気**: `Threads=5` (全コア)、`USI_Hash=512`、定跡オフ |
| 持ち時間 | 1 手 1 秒 (秒読み)、ponder なし。手番でない側は待つので、手番側が PC 全体を使える |
| 開始局面 | `openings.txt` の 64 定跡を先後入れ替え (ペア計測) |
| こちら | `usi_engine_native.sh` (C++ 探索)、モデルは下表のとおり |

対局中は自己対局の強化学習を一時停止する (`~/loop/match_paused.sh`)。止めないと
GPU と CPU を取り合い、こちらだけが不利になる。

## 改善ループ

1 周の流れ:

1. **測る。** どこが律速かを数字で出す (探索の時間内訳は `uct_profile`、
   棋力は上の表)
2. **一番効きそうなものを 1 つ直す。** 期待値を先に書く
   ([Improvement Backlog](Improvement-Backlog))
3. **A/B で確かめる。** 速度の変更は固定プレイアウトで 50 % (挙動不変) と
   playout/s、探索の質の変更は対局で ([Evaluation and Rating](Evaluation-and-Rating))
4. **採用したら本気の水匠と測り直し、この表に 1 行足す**

モデルは、渡された `checkpoint.pth` を出発点に**自己対局だけ**で鍛える
(他の AI を教師にしない)。昇格ゲート付きの強化学習が裏で回っていて、
ゲートを通った最良モデルがこの表のモデル欄に入る。

## 分かっていること

- **探索は GPU 律速。** `-DNDEBUG` を付け忘れていた C++ 探索を直したら、
  降下 (木の操作) は探索時間の 75 % から 25 % に下がり、残りは GPU 待ちになった。
  10×192 をバッチ 32 で回すと RTX 2060 の上限は約 15,000 局面/s
- **CPU は余っている。** こちらは 1 コア + GPU しか使わない。余ったコアで
  ルートの df-pn 詰み探索を並行して回している (9 手詰めを約 20ms で見つける)
- **最大の伸びしろはモデル。** 読みの量を 6.6 倍にしても差はまだ約 380 Elo ある
